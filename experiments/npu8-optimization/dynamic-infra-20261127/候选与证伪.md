# 动态 eager HSTU 的 Infra 候选记录

本轮使用 01 分块 overflow、原 ZeRO-2 梯度分区及 norm、Task Queue Mode 1。基线和候选均按同一份 shape 序列直接生成输入。编号 D01–D05 属于动态台账。

| 候选 | 函数与 trace 锚点 | 触发与实现 | 证伪条件 |
|---|---|---|---|
| D01 提高 CANN executor 缓存容量 | op-plugin `hit_cache` → `PTAGetExecCache`，miss 后进入 `*GetWorkspaceSize`。按算子与步内重复键计数 | 默认容量与 `ACLNN_CACHE_LIMIT=65536` 使用同一个 stock wheel。每步约 9,893 次查询。扩大容量可能让新 shape 下的重复小算子复用已经准备好的 executor | 稳态命中不增加，或正反序整步和独立 Free 数据不能支持所报指标。只有逐流实际工作和计数核对通过，才归因为等量提交 |
| D02 规范化 embedding 反向索引视图 | `op_api::embedding_dense_backward`，`add_param_to_buf`，`ConvertType`。基线 #4/#5 每步 1,027 个请求、6,159 次 kernel 提交 | 只处理满足守卫的只读三维 int64 视图。以 512 字节为单位移动描述符基址，保留余数 offset 和可达范围，对 key、地址重绑和描述符同时生效 | 最后一个表、重复 ID、padding、跨 shape 或非合格布局出现梯度错误，立即停止。若没有守卫命中、workspace 准备没有减少，或两序无端到端收益，则不归档为成功 |
| D03 直接构造 BF16 权重拆分视图（既有 #43） | 权重回写后 `aten::unflatten_dense_tensors`。新动态 #4/#5 各一次，17.515/17.840 ms 内没有关联设备工作 | 复用既有 TorchNPU 守卫和 `as_strided`。两腿都关闭图、41 和梯度打包。测 Host 侧视图数量、末任务到下一步供给间隙 | 实际回写没有命中、别名或版本语义改变、设备工作增加，或缩短的 scope 无法在配对整步观察到 |
| D04 跨分配流 D2D（既有 #44 的动态增量） | 反向主线程的连续 1,052 个 `InplaceCopy` 各发一次 SDMA。新动态两步该组对应空档 66.61/76.48 ms | 两腿固定同流 #42，候选对有真实跨流源、连续独立 BF16/FP32 存储、合法范围和对齐的复制记录源 stream 后直接提交 SDMA | 跨流守卫没有命中、源在异步复制前被复用、提交数变动或端到端不改善。若事件数因跨流存活管理变化，分别列出控制事件与实际数据工作 |
| D05 前向 embedding 权重和索引描述符 | `op_api::embedding`、`add_param_to_buf`、`ConvertType`。首次 #4/#5 各 1,027 笔请求、1,026 笔可见 workspace API，该 API 与后继空档交集 21.4 / 8.4 ms | 只为符合守卫的侧表权重和索引计算规范化的基址、offset 和可达长度。每步 1,024 对可复用描述符的输入，单独切前向开关 | 逐表输出或梯度改变，workspace 留在原水平，实发核数与机制不符，或完整正反序无法复现整步缩短 |
| D03 修订，混合 NPU flat 和 Meta 模板 | `torch._utils._unflatten_dense_tensors` 调用原 op 时未命中原版 #43；每个正常更新步有 1,052 个 Meta 模板，每个模板各建 narrow、slice、as_strided、view | 在隔离的 TorchNPU 包中适配 PyTorch helper，受守卫调用 C++ `try_unflatten`，按 flat 的原 storage_offset 构造标准别名视图。正常更新预计每步命中一次，溢出跳步不命中，单模板桶回退 | 真实训练未激活、版本计数或别名异常、梯度/权重不符、设备任务变化，或整步收益无法随正反序复现 |
