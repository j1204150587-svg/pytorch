# PR 42634 在 eager RMS 反向中的两笔提交

在已启用 native RMS 的 HSTU 中，每步 9 个 RMS 反向节点在物理流 47 共触发 139 笔工作。两序这 9 个范围和官方 Free 的交集约为 1.84、1.89 ms/步。分支从 `NativeRowRms::backward` 的两组元素乘法入手。第一笔 Triton 核写出梯度直达项、逐行归约输入和权重归约输入。第二笔处理方差梯度。两个归约及三次幂都用原生 ATen，各算术边界保留 BF16 转换。两个核在实际尺寸上逐行执行，首次用原 launcher 加载，在相同设备和参数布局下调用 PR 的真实 native plan。逻辑 grid 超过 40 时使用单独验证的物理 grid 扩展。若任一梯度分支出现位值差异，该版本即停止性能测试。[原节点与范围实测](../rms_native/README.md) · [两个 kernel](kernels.py) · [真实 launcher 布局和守卫](plan.py)

逻辑 NPU 8、Mode 1，两条 stream，共 60 个实际形状、68 个样例。两个 kernel 分别成功创建 1 个 plan、直接提交 25 次、物理 grid 截断提交 42 次。直达项和权重梯度在所有样例一致，方差项在 68 个样例均出现有限值差异。在首个 [1,13] 的 832 个元素中，169 个不同，首个差异为 BF16 位值 15346 与 15345。该双核实现进入「尝试无优化路径」。保留原生方差尾部，只融合前三个输出，使用独立的 68 例门和单独的 C++ 尾部进一步定位。[68 例实测及 kernel 哈希](npu.json) · [逐边界复核](locate.py)
### 保留原生方差尾部的实机复测

对照相同的乘积、行归约、方差尾部和三路输出，前缀融合加原生 C++ 尾部在 68 个样例中全部逐位一致。局部边界探针将首轮差异定位到 Triton 方差尾部：给它输入原生行归约和三次幂仍会复现差异。只保留逐位通过的前缀时，四个交替顺序的同步窗口分别为 106.62→126.55、102.59→127.17、91.71→117.25、92.08→115.80 µs。每窗 64 次，轮换四种形状。两种实现均列入「尝试无优化路径」。[68 个样例、边界差异和四次计时](../diagnostics28/rms-grad-prefix-v2-1795828248010319893/micro.json) · [完整探针](locate.py)
