# 连续侧表索引变换与原生转置的独立探针

前一版融合核的 2,048 字节输出对四种代表形状均至少触及 64 个不同的 128 字节区段。对 [4,31]，单核占用约 1.68 ms，原先 9 个设备工作有效时间合计约 0.20 ms。[首版逐笔实测](../side_ids/RESULTS-v1.md)

该探针沿输入的 token、表和 feature 顺序读取，连续写入 token-major 临时张量，然后调用原生 `movedim(...).contiguous()` 转为 embedding 所需表序。每个 Triton program 处理同一 token 下连续 512 张表的 2,048 项，两次下发分别负责边界判定与偏移加法、稠密转置。offset 来自实际输入张量，保留 int32/int64、非法值和有符号极值。A 使用原 ATen，S 与 P 分别由普通 launcher 与经当前 runtime 核验的 C++ 计划提交同一稠密核。[变换内核](kernels.py) · [调用与回退](operator_impl.py)

微测先在两条流上覆盖 60 形状、两种整数类型，以及非连续输入、几何回退和跨流提前释放。全调用窗口包含临时张量分配、两次下发和首尾同步。另测稠密核与实际转置的独立窗口。Level1 的 36 个 marker 用来核对三条路径的算子、物理流、工作数和 P 真实命中。完整调用对原 ATen 的同步差异决定是否进入训练。[自包含实机包](../side-ids-dense-v2.tgz) · [设备探针](probe.py) · [物理任务和窗口核算](verify.py)
