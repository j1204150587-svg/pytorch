# Attention score 修正索引后的实机微门

在设备端显式将 BF16 查表键限制为 0–65,535。60 种动态形状与边界值共 66 组，在两条 NPU stream 上交替运行。普通 Triton 和 C++ 计划相对原生的 attention 输出及 dQ、dK、dV 均逐位相同；内层 scores、dScores 的 12 组也全部逐位相同。两个真实核各准备一次计划，语义门内记录 66 次直接提交和 88 次按物理网格上限提交。[实际运行的代码、调用命令与逐例结果](../score-tiles-v3-1046.tgz) · [索引纠错证据](LOOKUP.md)

|---|---:|---:|---:|---:|

每个 S 窗口有 96 次普通 Triton 提交，每个 P 窗口有 48 次直接提交和 48 次按网格上限提交。P 相对 S 的窗口耗时在两种执行顺序下均缩短。P 对原生 N 的前三个窗口方向不一致，第四个 N 有明显长尾。本次记录来自单独的 attention 计算，整步端到端、Free 及同流设备计数仍需各自训练收据。[逐窗和逐核计数](verified-v3.json) · [原始包复算](verify_v3.py)
