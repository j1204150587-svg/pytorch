# 侧表索引融合 v1 实机结果

在 60 个不同的训练 shape 上分别使用 int32 和 int64，交替两条执行流。A 为原 ATen，S 为一个 Triton 核，P 用经实机 ABI 核验的 C++ 计划提交同一二进制。120 组 A/S/P 结果均与独立 CPU 地址计算逐位一致。P 各 dtype 冷启动一次，随后真实命中 118 次。四个非标准输入走回退，跨流提前释放后的张量也逐位一致。[原始命令、微测与 trace](../sideids-0959.tgz) · [源文件哈希及每个窗口](verified-v1.json)

每个无 profiler 窗口循环四个形状 48 次，首尾同步。下表为完整调用的 μs/次。

| 顺序 | A 原 ATen | S 普通 Triton | P 同核 C++ |
|---|---:|---:|---:|
| A/S/P | 139.232 | 744.538 | 744.191 |
| P/S/A | 141.052 | 746.144 | 745.318 |
| A/S/P | 138.475 | 744.061 | 743.735 |
| P/S/A | 141.002 | 746.466 | 744.836 |

在预分配相同输出时，四个 S/P 与 P/S 窗口的 S→P Host 中位时间分别为 115.30→68.77、111.41→68.03、106.17→67.63、119.53→68.57 μs。首尾同步的每次耗时仅少 1.51、2.13、5.25、2.02 μs。普通核和计划核均比原 ATen 慢约五倍。

设备时间取每个 shape 三次中位数。12 组各有 A/S/P 共三个同步标记，均无跨界工作；每组 A 的 9 笔和 S/P 各自的单核均在物理流 47，P 在全部标记实际进入 C++。64 张表每次写各自的 4 个 int64，连续 32 字节后已到下一张表，两张表对应输出首地址的步幅为 608、896、1,408、3,968 字节。每个 tile 的 2,048 字节输出至少分布到 64 个不同的 128 字节区段。单核占用设备的大幅增长抵销减少的 8 次提交，v1 止于微测。训练中的原始空档来自另两份 Level1，详见侧表准备区间。[逐个 marker、task ID 与真实流](physical-real.json) · [两份训练中的调用边界](README.md) · [实机微测复算](verify_v1.py)
