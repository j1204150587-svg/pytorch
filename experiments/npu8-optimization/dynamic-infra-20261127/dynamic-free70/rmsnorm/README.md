# HSTU RMSNorm 的 eager 下发筛查

四个 HSTUBlock 各有一个输入 RMSNorm 和一个输出 RMSNorm，加上输出 projection 前的最后一个 RMSNorm，每训练步执行九次，宽度均为 64。原模型按 `x.pow(2) → mean(-1) → 加 eps → rsqrt → 乘 x → 乘 weight` 执行。BF16 的平方、均值、加法、倒数平方根及两次乘法各自产生可观察的中间舍入。模型权重反向需要第一次乘法的 BF16 结果。

第一项直接调用 TorchNPU 的 `npu_rms_norm(x, weight, epsilon=1e-6)`，取第一个返回值。是否保持现模型的舍入顺序由输出、输入梯度和权重梯度的逐位对照判定。

第二项保留原四个算子和它们的反向实现。在一个 Triton 调用内先写 `z=BF16(x*inv_rms)`，再以舍入后的 z 计算 `BF16(z*weight)`。反向将四个逐元素乘法合并，用相同的 BF16 中间量分别生成直接传给 x 的梯度、inv_rms 的分项和 weight 的分项；两次广播归约仍用 ATen 的 `sum_to_size`。这些改动的理论上限是每个 norm 减少 1 个前向、3 个反向逐元素算子提交。实际设备提交数和端到端收益需要后续配对；若上游梯度不连续，候选还可能需要一次连续化。[算子与守卫](rms_candidate.py) · [Triton 实现](rms_kernels.py)

微测使用 `[1,19]`、`[2,14]`、`[2,22]`、`[4,31]`，每个 shape 分别覆盖随机输入配单位权重、随机输入配有正负值的权重、接近 eps 尺度的输入和全零输入。三项输出都逐 BF16 位比较，失败项保留差异数和最大绝对差。仅对全部通过的候选做 4 个相邻正反序同步窗口，每窗口轮换四个实际 shape，执行前向及标量 loss 的反向。每次调用的计时含相同的 loss 标量化，设备同步仅在各窗口首尾执行。[微测入口](micro_gate.py) · [16 例 CPU 梯度与输出检查](cpu-micro.json)

~~~sh
python -B micro_gate.py --device npu --repeats 96 --out <本次微测输出>.json
~~~

该实现仅用于一阶训练且输入为三维连续 BF16、末维 64。未通过任何一项位级检查或相邻配对无法支持时延下降，就不将该路径作为已验证的 HSTU 训练收益。
