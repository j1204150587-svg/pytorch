# 三个 Infra 补丁的整包稳定性测试

目标提交为 `e3cda6399cb194c813530222478ea018f5aca5c9`。原训练的 10 个工作区文件与 runner 逐腿核对指纹，目标为逻辑 NPU 8、板 4/chip 0、单 rank、1,024 张侧表、01 分块 overflow、梯度累积 1、BF16 ZeRO-2、seed 1234、Task Queue Mode 1。60 个互异合成形状的 batch size 为 1–4、序列长度为 12–32。以同一进程内第 4–6 步的实际 shape [1,19]、[2,14]、[2,22] 采集 Level0。

|实验|A|B|可回答的问题|
|---|---|---|---|
|fixed-cache|新构建，三个开关全关，缓存 65,536|同一构建，三个开关全开，缓存 65,536|按既有大缓存配方部署时，三个代码改动合计带来多少增量|
|default-cache|新构建，三个开关全关，缓存环境变量未设置|同一构建，三个开关全开，缓存环境变量未设置|使用镜像默认缓存策略时，三个改动自身的收益|
|stock-to-full|镜像原装 TorchNPU，默认缓存|新构建，三个开关全开，缓存 65,536|从现有镜像原装方案切到完整配方的总收益|

三个开关分别为 `NPU_DYNAMIC_REBASE_INDICES`、`NPU_DYNAMIC_REBASE_FORWARD` 和 `TORCH_NPU_QUEUE_NOTIFY_FULL_ONLY`。前两项在构建时接入 op-plugin 的规范化描述符和 executor 缓存键，第三项修改 PTA 队列的唤醒条件。缓存容量是单独的 CANN 配置。实验中记录训练 worker 的库映射、开关值和缓存变量是否存在。

每种比较预排六个无 profiler 配对，正序 A/B 和反序 B/A 各三对。不同配置交错执行，每个训练进程预热 10 步后用首尾同步窗口测 50 步，实际工作量为 136 个样本、2,994 个 token。每种比较预排四个独立 Level0 配对，两序各两对。所有配对使用宿主共享锁，逐腿核验设备与 worker。记录每一对的步时、吞吐、A−B、正反序分布和异常值。Free 占比按对应窗口 ΣFree/ΣStage。无 profiler 和 Level0 分各自窗口计算。

每种比较先跑原训练相同前 8 步的数值审计。fixed-cache 另开计数验证三项均命中，并用独立双腿覆盖索引/权重、顺序和回退边界，以及真实 ZeRO-2 非有限梯度跳步。性能测量关闭计数。两个同包比较另做 Level1，核实 eager 算子、物理流、workspace 查询和设备提交数。分析区分同一实际 shape 的首张侧表与后续侧表。对同一开关组合的正反顺序使用独立进程和实测 A 腿，收益按本次成对结果计算。
