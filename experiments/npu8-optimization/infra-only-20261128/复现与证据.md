# 实机命令与原始文件

宿主实验目录为 `/data/recsys-gr-ds019-host88/artifacts/infra-only-20261128`，容器内对应 `/artifacts/infra-only-20261128`。原始部署在相邻目录 `dynamic-shapes-20261127/deploy.hFNaMd`。本轮 archived-runner 中的 run_suite.py 与该目录的 run_suite_v2.py 字节一致，其余入口、补丁和配置按 reference.json 固定。原 runner 将最初动态配方物化为 10 个文件后，两腿在同一个工作区运行。训练前后均校验完整集合及 SHA-256。[指纹](runner/reference.json)

每个配对的 result.json 记录宿主原始 session 的绝对路径。session 中保留 profiler 的原始目录、全部 CSV、trace、训练日志及环境。导出证据的 raw 目录保留两腿的形状、同步窗口、官方 CSV、压缩 trace 和状态。pairs 目录另有每腿的 effective docker argv 以及实际 worker 的 /proc 映射。md 表格从未舍入的同步秒数和三步 CSV 复算。

```sh
cd /data/recsys-gr-ds019-host88/artifacts/infra-only-20261128
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs-audit.json --out pairs/new-divs-audit --mode audit --order ab
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs.json --out pairs/new-divs-no-profiler-ab --mode no-profiler --order ab
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs.json --out pairs/new-divs-no-profiler-ba --mode no-profiler --order ba
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs.json --out pairs/new-divs-l0-ab --mode l0 --order ab
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs.json --out pairs/new-divs-l0-ba --mode l0 --order ba
python3 -B runner/host_pair.py --runner archived-runner --recipe recipes/divs.json --out pairs/new-divs-l1-ab --mode l1 --order ab
python3 -B runner/paired_metrics.py --schedule archived-runner/dynamic_shapes_npu8.json --round pairs/new-divs-no-profiler-ab pairs/new-divs-l0-ab --round pairs/new-divs-no-profiler-ba pairs/new-divs-l0-ba
```

其余实验采用相同命令，将 divs 改成 addmm、mm、queue、emb-back 或 emb-fwd。每份正式 recipe 和 audit recipe 的环境变量及库哈希可由配对的 recipe.json 复核。每腿只在真实容器内增添当前原生环境，torch_npu 的其他包文件按 stock 逐项核对。记录 selector 仅用于宿主区分顺序，转交给真实 docker 之前会剔除。整对运行持有公共锁 `/run/lock/recsys-gr-ds019-npu8.lock`。

正式 Level1 的 `trace_view.json.gz`、`kernel_details.csv` 和 `step_trace_time.csv` 由原 runner 留在每腿目录。用前一轮的 compare_dynamic_legs.py 按 queue correlation、HostToDevice flow、CANN connection 和物理 stream/task 解析，加上本轮 cohort.py 筛选机理适用的调用。按顺序保留 A/B 的物理流、请求与设备提交数、各阶段分位数和与后继设备空档交叠的时间。各阶段的 p95 不能相加还原墙钟。[归因实现](cohort.py) · [公共解析器](https://github.com/j1204150587-svg/pytorch/blob/7e923d3ca83f91c54ff3f2c633ce9de15f84634e/experiments/npu8-optimization/dynamic-infra-20261127/analysis/compare_dynamic_legs.py)

独立算子微测在对应的 operator_probe.py 外层持锁，实际命令保存在每个微测的 command.json。微测使用单独的 Python 进程。原训练的数值门采用 runner 自带的 `--audit-state`，所有正式时间窗均关闭数值门。实际形状和相同步号按 metrics.json 核对，原训练使用相同 seed 和输入生成器。该 runner 在标准稳态腿中没有逐步导出输入内容哈希。
