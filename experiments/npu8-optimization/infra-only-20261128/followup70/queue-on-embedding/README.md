# 双向 embedding 基线上的满队列唤醒

`Repository::Dequeue/Enqueue` 在满环 producer 没有登记等待时省去 consumer 写 eventfd。两腿都启用双向 embedding 描述符规范化和 CANN cache 65536，然后仅切换这个策略。八步两个进程均消费 87,845 项，满环等待者登记均为 0。A 写 86,762 次且全部未观察到等待者，B 写 0 次。这是 host 系统调用计数。[原生补丁](producer-wake.patch) · [实际计数](counts.json)

原生库 SHA-256 为 `3c2bd66fb20342176c79f9c68685cd23d0cd387003e8e4790c7fa047c7e31073`。正反序裸跑缩短的幅度差异很大，正序 Free 升高。反序 Level0 和 Level1 尚无已完成结果，无法确认 Free 双序改善或物理提交数，归入尝试无优化路径。独立的有限值、+Inf、NaN、−Inf 七步探针两腿均执行四次有限更新，三次非有限输入都跳步；输入轮换 [1,19]、[2,14]、[2,22]。[原始收据与 overflow 输入输出](training-receipts.tar.gz)
