# 双向 embedding 下的队列唤醒增量

原 `Repository::Dequeue/Enqueue` 补丁在原装缓存及未规范化 embedding 的双序端到端均缩短。双向描述符规范化后，Level1 两步的全部后继设备空档中，18.466、12.460 ms 与对应任务的可见排队等待相交。现在 producer 的参数准备已明显缩短，旧数据无法给出同一补丁在这条提交链上的增量。此次将原补丁的同一目标文件与双向 embedding 库链接，固定 65,536 缓存，在同一新库内只切换满队列等待者唤醒。[已有队列补丁](../../queue/producer-wake.patch) · [当前配方空档](../../embedding/analysis/emb-fwd/RESIDUAL.md)

审计核对任务消费、满环登记、无等待者时的 eventfd 写和 8 步训练状态。正式裸跑与 Level0 均做两序，Level1 匹配同一步的算子、stream 与物理提交。如果少写 eventfd 后双序步时或 Free 未见稳定改善，按实测结果归档。
