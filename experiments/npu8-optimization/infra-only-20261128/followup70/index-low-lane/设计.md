# embedding 反向的 int64 索引物化与窄化

双向 embedding 的原始 Level1 第 4 步出现 1,024 个反向 AsStrided、3,081 个反向 Cast。Ascend 910_9362 的公开 v9.1.0 `aclnnEmbeddingDenseBackwardGetWorkspaceSize` 在 DAV_2201 的小矩阵分支先执行 `Contiguous(indices)`，之后将 int64 索引转成 int32。候选仅针对该反向路径。小端设备上若 int64→int32 对所有输入都等于取低 32 位，可将每个 int64 的低半部描述为 stride 加倍的 int32 视图，把两次设备工作合为一次物化。无跨步数据缓存。预期每个合格反向请求少一个 Cast，实际提交数以 Level1 重数。[固定源码](https://github.com/Atlas-Ascend-Fork/ops-nn/blob/ceb4536a2bd6fc99b85aec9d0fdcc0f470376292/index/embedding_dense_grad_v2/op_api/aclnn_embedding_dense_backward.cpp#L346-L374)

先在实卡检查极值、超 int32 范围、正负数、非零偏移与 60 个 shape。参考为同机同包的 int64→int32 Cast，两种表示要逐位相同。原算子与候选算子使用同一组合法重复索引、梯度及 padding，对比完整权重梯度。热描述符要保留规范化后的命中，并区分实际 AsStrided 与 Cast 数量。如果整数窄化语义不一致或视图会在 PTA 内触发额外设备操作，就先在独立探针结项。
