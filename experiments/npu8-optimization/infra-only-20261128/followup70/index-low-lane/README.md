# embedding 反向在物化索引时一并窄化

正序每步缩短 25.36 ms，反序每步增加 29.30 ms。Free 占比在正序下降 2.096 个百分点，在反序升高 1.754 个百分点。实际设备提交数双序计时前已逐笔核验，现有两组训练结果不足以将这项改动计入获益配方。[双序八列与配对波动](双序结果.md)

原训练的侧表索引形如 [B,L,4]，每个元素为 int64，三个轴的 stride 以 8 B 为单位。目标 Ascend 910_9362 上的原始 embedding 反向先把索引物化为连续张量，再转为 int32。op-plugin 在已有反向描述符规范化的作用域中，给满足 dtype、张量几何、SoC 与参数限制的请求绑定原 storage 的低 32 位视图，按 4 B 单位重新表达 stride 和 offset，并同步修改 executor 缓存键。第一个物化任务随即产出 int32。两腿共用 65,536 项缓存和双向 embedding 规范化。[实现补丁](index-low-lane.patch) · [守卫、极值与证伪条件](设计.md)

原训练八步 A 命中 0 次、回退 8,216 次，B 命中 8,192 次、回退 24 次。两腿梯度、norm、最终权重和 AdamW 状态一致，loss 最大绝对差 5.72×10⁻⁶。独立双流探针覆盖 60 个形状和一次形状复访，122 个目标调用与 CPU 参考逐位一致，另有 3 个回退用例。七步独立 ZeRO-2 检查中 B 实际命中 7 次，两腿均做四次有限更新与三次非有限跳步。[训练计数](counts.json) · [双流实包回执](native-gate-results.json) · [探针、命令、构建收据与异常输入输出](repro.tgz)
