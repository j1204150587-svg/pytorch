# embedding 热缓存工作区的 Host 句柄

op-plugin 的 `hit_cache` 从 CANN 取回 executor 和非零 workspace 大小时，固定版本的 `OpPreparation::unsafe_empty_workspace(size)` 除了向 NPU caching allocator 申请字节，还创建临时 NPUStorageImpl 和 NPUTensorImpl，刷新 stride；返回值只用于取存储地址。应用点是每步各 1,027 次的 eager embedding 前反向。既有双向规范化 Level1 第 4、5 步每方向只剩 18 次可见 GetWorkspaceSize。热命中时是否有非零 workspace 需要以新计数验证。

只在 Mode 1、非 capture、该两处的热命中上，用原分配器的 DataPtr 在 producer 上持有同一生命周期，按原次序提交同一地址参数。零字节路径直接返回空指针。冷 miss 沿用原宏，保留 capture、非 Mode 1 与异常回退。A/B 共用同一库。若非零命中少、分配大小不对应、准确性失败或微测两序稳定回退，则按相应证据结项。实际设备工作和单次 ACL 要用同流同请求 Level1 核对。统计构造次数与字节数的运行单独于性能窗。
