# 动态 HSTU 收尾局部归因

逻辑 NPU 8、单 rank、BF16 ZeRO-2、1,024 张侧表、01 分块 overflow 和 Task Queue Mode 1。训练 trace 启用双向 embedding 索引描述符规范化与 65,536 项 CANN 缓存。第 4、5 步的实际 shape 分别为 `[1,19]`、`[2,14]`。以下四项提供设备任务数、Host 路径开销和调度位置证据；均无已验证的端到端或 Level0 Free 收益。

## 二维 DMA 会按行提交设备任务

侧表每行只取 4 个 INT64，宽 32 B、源行跨度 32,768 B、目的行跨度 32 B。原训练前向和反向每步各有 1,024 笔同流 AsStrided，每次连续化只需 1 个设备任务。两步中，紧邻前向任务的全流空档合计 46.037、42.779 ms，反向为 3.852、4.426 ms。这些空档只能定位后继工作。设备能否一次取完所有行决定了这项替换是否能减少提交。

60 个合成 shape 的二维 D2D 返回码及流同步返回码均为 0，两个流轮换，覆盖表号 0、15、1023，结果与 CPU 切片逐位相同。下面三次局部 Level1 均只有一次公开 `aclrtMemcpy2dAsync` 调用。CANN STARS Runtime 每次只复制 32 B，再将两端地址推进一个行跨度；物理轨道确认为每行一个 MEMCPY_ASYNC。

| 实际 shape | 物理流 | 独立连续化 / 二维 DMA 设备任务数 | 两者设备执行时间之和 µs |
|---|---:|---:|---:|
| [1,19] | 47 | 1 / 19 | 3.38 / 13.40 |
| [2,14] | 45 | 1 / 28 | 3.46 / 21.30 |
| [2,22] | 47 | 1 / 44 | 3.18 / 35.18 |

独立连续化微测使用 `aclnnInplaceCopy_SliceAiCore_Slice`，原训练侧表使用 embedding executor 内的 AsStrided。两种路径均只需一笔设备工作。二维 DMA 的候选机制在算子微测中被证伪，未接回训练。[设备与命令原件](embedding-dma2d/probe-evidence.tgz)

## release 环的名称复制只占较小的 Host 预算

PTA 在 `CopyReleaseParamFunc` 的 OPAPI 分支调用 `ExecuteParasOpApi::Copy`，其中 `strncpy` 将操作名称填充至 99 B。目标 release 槽随后把 handler 移交 release 线程。原 wheel 的八步 A/A 收据显示，每个完整进程进入 release 入口 87,845 次，其中 80,233 次经过 OPAPI 名称复制分支，约 91.335%。计数含初始化与收尾。两腿梯度、norm、权重和 AdamW 状态一致，loss 最大绝对差 3.815×10⁻⁶。两腿都运行原实现，这次训练验证的是分支频次。

用同一镜像、真实名称顺序和槽布局做 CPU 微测，源 handler 移空、目的 handler 执行以及共享对象释放均通过。8,192 槽、每种捕获方式 16 个 ABBA 分组，省去名称复制的配对中位差为 8.981 ns/项（小对象）和 8.229 ns/项（堆捕获）。按 Level1 两步的 9,892/9,893 笔 aclnn 命名请求折算，得到 **0.081–0.089 ms/步的 Host 局部预算**。release 槽的 C++ 对象生命周期也需单独处理，CPU 微测未将这项修改带入训练。[A/A 原始计数及训练数据](release-name/evidence.tar.gz)

## 四个 producer 调度窗口中的长空档

另一次相同实现的 Level1 A/A，使用两腿各自的 scheduler switch、固定 TID 用户态采样、校时锚点和设备全流工作区间。对每个已链接空档，只取空档开始至负责后继提交的 producer 进入对应 ATen 之前的部分。名义前缀按 trace 原时间计算；保守前缀收紧主机与设备时钟误差后再和线程运行区间求交，二者不可相加。

| 腿 / 步 | 名义前缀 ms | 保守部分在 CPU 上 ms | 抢占换出 ms | 其他换出 ms | 最长保守前缀 ms |
|---|---:|---:|---:|---:|---:|
| A / 4 | 96.996 | 37.626 | 0.182 | 2.241 | 13.755 |
| A / 5 | 79.133 | 39.245 | 0.000 | 3.366 | 13.306 |
| B / 4 | 128.870 | 40.744 | 0.000 | 1.964 | 18.103 |
| B / 5 | 99.203 | 38.028 | 0.000 | 1.440 | 16.610 |

四个最长区间均位于物理流 47 的 `aclnnMul` 所属 ATen 进入之前，后继提交者为 autograd 线程。此时后继算子尚未开始准备参数，缩短它自身的提交耗时无法直接消除这个前缀。保守区间内共 75 个实际 on-CPU 样本，栈顶分别落在 CPython 24 次、PyTorch CPU 14 次、PyTorch Python 绑定 12 次、libc/分配器/系统运行库 20 次、NPU 软件栈 4 次及 profiler 1 次。样本间的 CPU 耗时与 off-CPU 的具体等待对象仍未知。[双腿 perf、逐空档调度状态、时钟与原始 Level1](producer-sched/raw-evidence.tar.gz)

## ACL 属性查询的实测预算

原双向 embedding trace 中，`aclrtGetStreamAttribute` 均来自 consumer 的 dequeue 区间。表中“自身后继空档”要求查询和该次 dequeue 的后继物理任务属于同一队列请求；其他交集只要求时间重合。交集使用名义校时，两项 API 不作跨线程相加。

| 步 | API | 次数 | 全部调用区间并集 ms | 与全流空档交集 ms | 与自身后继空档交集 ms | p50 / p99 µs |
|---|---|---:|---:|---:|---:|---:|
| 4 | GetStreamAttribute | 9,892 | 3.234 | 2.919 | 2.351 | 0.30 / 0.70 |
| 5 | GetStreamAttribute | 9,893 | 3.095 | 2.788 | 1.451 | 0.30 / 0.59 |
| 4 | GetResInCurrentThread | 4,528 | 1.666 | 1.349 | 未建立关联 | 0.22 / 0.93 |
| 5 | GetResInCurrentThread | 4,534 | 1.611 | 0.917 | 未建立关联 | 0.28 / 0.90 |

对两个已通过非空流指针检查的属性查询调用点，在同机 ARM CPU 上单测 `GetCurStream` 的非空分支。每批 65,536 次、51 轮交替 ABBA/BAAB，两颗不同物理 CPU 包上每次配对节省的中位数为 0.609、0.640 ns。乘实测约 9,900 次调用，仅对应 **0.0060–0.0063 ms/步**。这项微测覆盖 CANN 内部的一段指令；完整公开 API 还会做参数校验、属性读取等工作。上述热数据投影不能约束训练中的冷缓存长尾。没有实际修改 CANN 进行训练 A/B。原 trace、微测代码与逐轮 CSV 均在下方补充包中。
