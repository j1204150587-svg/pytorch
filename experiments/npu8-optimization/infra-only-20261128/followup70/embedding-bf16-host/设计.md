# embedding 反向使用已安装的 BF16 小维度内核

原双向 embedding 配方的第 4、5 步，每步 1,027 个反向请求中出现 3,081 个 Cast。CANN 9.1.0 的 `aclnnEmbeddingDenseBackwardGetWorkspaceSize` 会先把 BF16 grad 转成 FP32，执行归约，再把结果转 BF16。板 4 的 Ascend910_9362 镜像还安装了 `EmbeddingDenseGrad_bf16_high_performance.o`。对应小维度内核会在片上将入口转 FP32，执行 FP32 累加，最后以 CAST_RINT 写回 BF16。测试只在 CANN Host 为这一个已有物理实现组装 executor，索引的连续化与 INT32 Cast 保持原路径。候选与低 32 位索引实验独立。[原 Host 路由](https://github.com/Atlas-Ascend-Fork/ops-nn/blob/ceb4536a2bd6fc99b85aec9d0fdcc0f470376292/index/embedding_dense_grad_v2/op_api/aclnn_embedding_dense_backward.cpp#L331-L413) · [小维度内核](https://github.com/Atlas-Ascend-Fork/ops-nn/blob/ceb4536a2bd6fc99b85aec9d0fdcc0f470376292/index/embedding_dense_grad_v2/op_kernel/embedding_dense_grad_v2_small_dim.h#L143-L303)

首门在卡 8 上用同一组真实 strided 索引与输入，分别运行原 ACLNN 和私有 Host 入口。先验核查两个流、60 个形状、不同 storage、padding、重复 ID、正负抵消、有限极值、非有限值，重复运行原路径以分辨 run-to-run 漂移。只对固定 SoC、非确定性小维度模式、BF16 grad 和输出、int64 索引的已验证形状放行。如位级一致性门失败，逐项复核原腿自身重复结果和 device error。如微窗双序都退化或物理 Cast 未减少，记录证伪。通过后方可接回原生 eager 调度，并核验训练误差、实际设备工作和正式步时。
