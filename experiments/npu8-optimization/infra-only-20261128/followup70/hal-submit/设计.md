# CANN Host 向驱动提交 SQE 的实测边界

旧的 Level1 在每步约 15,000 笔 kernel launch 上记录了 ACL 与 Node，驱动内部的 `halSqTaskSend` 没有对应的可见事件。实测镜像 `libruntime_v100.so` 将它列为外部弱符号。v9.1.0 源码的 `AllocTaskAndSendStars` 在同一 stream 上为任务准备 SQE、登记队列并调用该接口。采样热点在这条调用链中。[CANN 提交源文件](https://github.com/hicann/runtime/blob/0b4af8a31c75a1f1f43638a8f75b9e3c6182e031/src/runtime/core/src/task/task_submit/v100/task_submit.cc#L395)

同库、同一原动态 runner 的独立 Level1 A/B 仅切换驱动提交计时。在 B 保存每次成功或失败的返回、起止、SQ ID、队列项数和已返回的位置。原调用的次序和参数一致。按训练 worker 与 consumer tid 验证覆盖，逐个关联 ACL 区间和后继物理任务。驱动 API 内时长和它与全流空档的重叠给出这个区间可直接解释的观测预算。批量提交另需证明多个独立操作可以按原流依赖一次安全发布；连续的 SQ 位置本身无法证明这一点。该运行用于定位，不作为端到端收益。
