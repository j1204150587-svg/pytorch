各步 HAL 调用均成功，每次发送一个 SQE。SQ 2、4、5 分别唯一映射到物理流 47、45、44。可关联任务的实际 Task ID 减驱动返回的 SQ 位置，对 2,048 取模，流 47 恒为 1，另两流恒为 0。此项独立于时间戳，核验了逐笔身份。[每笔驱动、ACL、硬件与空档](calls.csv.gz) · [各队列和算子分位](result.json) · [位置与到达间隔](arrival.json)

进一步要求前后两笔来自同一次 eager dequeue、同一物理流、相邻的 SQ 位置，且前一项物理工作结束正好是全流空档起点。即使采用允许的最早设备时钟，第 4、5 步仍有 5,719、5,646 笔后继在前一项开始执行前已经从 HAL 返回。这些任务之间的设备空档为 8.928、9.197 ms，其中反向 embedding 占 8.755、8.928 ms。在这个子集上，驱动已经收到后继工作，缩短同一后继的参数准备无法直接消除两个设备任务之间的间隔。减少复合算子内部的物理任务仍值得单独检验。[相邻 SQE、同一请求与空档复算](already-sent.json) · [程序](ahead.py)

SQ 2 相邻的两次提交中，前一 HAL 返回至下一 HAL 开始若处于 2–5 µs，第 4、5 步分别有 4,764、4,823 笔，本次服务中位为 0.311、0.320 µs。间隔为 20–50 µs 时，本次中位为 1.700、1.710 µs。此处测到了请求间隔和服务时长的相关性。设备侧排队、跨流依赖及固件发起时机还需独立观测。每步约 21 ms 的完整 HAL 函数时长限定了这段代码自身的直接预算。

Host 的 CLOCK_REALTIME→MONOTONIC_RAW 由外部同时采集的时钟括号逐笔插值，再使用 profiler 的 `host/start_info` 映射。使用 23,905 组时钟样本，最大括号 510 ns。设备相对 Host 的常量偏移满足每个后继晚于同笔 HAL 调用开始，且全设备同步完成覆盖之前已提交的物理工作。两步的偏移范围为 −0.515 至 +145.250 µs、−13.110 至 +138.610 µs。两步各有 28 笔 HAL 调用缺少唯一对应的 ACL launch/memcpy，另各有 1 个已关联后继缺完整步内空档，上表分母分别列出。[时钟及分流敏感性](hal-bounds.json) · [测点](probe.cpp) · [关联](analyze.py) · [偏移复算](bounds.py)
