# 动态 eager 中的兼容选项查询

原训练两次 199 Hz CPU-clock 采样中，主线程和 autograd 线程的最内层 PTA 帧为 `CheckCompatibleImpl` 的样本分别是 15+10、17+11。实际调用点包括 capture 状态与上下文查询。原实现每次调用 `GetOption` 都从同一个长字符串字面量构造注册表键。候选只将键构造移到第一次查询，继续从原注册表读取当前值。配置存储、写入路径和 capture 路径均使用原实现。

先在同镜像用实库检查初始值、运行时修改、跨线程读取和不等于字符串 1 的值，再比对相同函数查询的正反序微窗。原训练审计单独打开调用次数与时间观测。默认性能腿关闭计数，只有两序微窗均改善且原训练命中才测量端到端与 Level0。两序整步无改善时列入尝试无优化路径。
